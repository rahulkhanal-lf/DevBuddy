# MindFlow AI — Source Guide

## Project layout

```
project/
├── decisions.md          ← all design decisions (LLM, chunking, k, temperature, CoT, etc.)
├── prompts/
│   ├── system_qa_v1.md   ← first-iteration system prompt (3 rules)
│   └── system_qa_v2.md   ← current system prompt (5 rules + CoT instruction)
├── results/
│   └── eval_results.csv  ← evaluation output (generated by eval/run_eval.py)
└── src/
    └── README.md         ← this file

BE-FastAPI/
└── services/
    └── rag_service.py    ← RAG pipeline: ingest_pdf, ingest_text, rag_chat, rag_chat_structured

eval/
└── run_eval.py           ← LLM-as-judge evaluation suite (10 queries, CSV + JSON output)
```

## Running the evaluation

```bash
# 1. Start in the backend directory so .env is loaded
cd BE-FastAPI

# 2. Run standard evaluation (k=4)
python -I ../eval/run_eval.py

# 3. Failure analysis — set k=1 to demonstrate score degradation
python -I ../eval/run_eval.py --k 1
```

Results are written to:
- `project/results/eval_results.csv` (required deliverable)
- `eval/eval_results_<timestamp>.json` (full detail with CoT reasoning)

## RAG pipeline components

| File | What it does |
|---|---|
| `BE-FastAPI/services/rag_service.py` | Ingestion, retrieval, generation, structured output |
| `BE-FastAPI/services/bedrock.py` | Bedrock client factory (`get_chat_model`, `get_bedrock_client`) |
| `BE-FastAPI/api/chat.py` | HTTP endpoint that calls `rag_chat()` |
| `BE-FastAPI/api/files.py` | File upload endpoint → calls `ingest_pdf()` |
| `BE-FastAPI/api/knowledge.py` | Knowledge text endpoint → calls `ingest_text()` |

## Key design choices (summary)

See `decisions.md` for full justification of each.

| Decision | Choice | Short reason |
|---|---|---|
| LLM | Amazon Nova Lite | In capstone account; 200k context; structured output support |
| Embedding | Titan Text Embeddings V2 | Best MTEB Retrieval score available in Bedrock |
| Vector store | PostgreSQL + pgvector | No extra infra; same DB as app data |
| Chunking | RecursiveCharacterTextSplitter | Respects paragraph/sentence boundaries |
| chunk_size | 1000 chars | Fine-grained retrieval with enough surrounding context |
| chunk_overlap | 100 chars | Prevents cross-boundary misses |
| k | 4 | k=3 missed multi-chunk answers; k=6 added noise without quality gain |
| Temperature | 0.1 | Factual QA needs near-deterministic output |
| CoT | Judge prompt | Eliminates length-bias in scoring; improves calibration |
